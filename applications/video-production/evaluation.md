# 评价方案：可控性是否减少返工

状态：方案，尚未执行真实模型对比。

## 先固定任务和验收

选择有权使用的固定素材与任务集，覆盖单主体、多主体、多镜头、动作参考、音画同步、局部编辑和续写。每项任务预先写明必须保持/必须改变的属性。

比较时记录模型 ID/版本、访问日期、分辨率、时长、输入参考、参数与随机种子（服务允许时）。不可访问的设置记为未知。按任务难度分层；将成功例和失败例一起保留。

| 维度 | 判断问题 | 建议记录 |
|---|---|---|
| 任务遵循 | 是否完成指定动作/编辑？ | 通过/失败及具体原因 |
| 参考对齐 | 身份、服饰、物品、风格是否保留？ | 逐属性评分与关键帧定位 |
| 连贯性 | 跨帧/跨镜头是否出现突变？ | 错误时间段和严重程度 |
| 非目标保持 | 无需修改的内容是否被破坏？ | 区域/主体及影响 |
| 声画 | 口型、动作、环境音是否同步且可用？ | 对齐偏差与人工判断 |
| 交付 | 无需重大返工能否进入后期？ | 预先确定的业务验收，不仅是好看 |
| 效率 | 从提交到可交付花多少资源？ | 排队、生成、重试、审片、后期时间与费用 |

## 每次候选的最小记录

`task_id`、`source_group`、模型/版本、输入引用、配置、候选序号、计费状态、延迟、评分、失败类别、审片时间、后续动作和最终是否交付。

人工评价尽量盲化模型名称，事先明确评分标准，并抽样复核分歧。统计包含任务数、样本量、失败与重试策略；任务难度存在差异时按同一任务配对比较。报告比例时记录不确定性，避免只展示最好的单个候选。

## 失败分类

至少区分主体漂移、动作未遵循、多主体混淆、时序破坏、参考泄漏、声音错误、文本错误和服务失败。技术失败与业务不适用也需区分：画面连贯但没有正确产品标识，可能依然无法交付。

本目录当前没有实测结果。外部论文的可用率与这里的业务验收不是默认同一指标。
